# ossian-stack

Ossian's personal agent skill collection, packaged as a Claude Code / Codex
**plugin**. One repo, which is also its own marketplace.

These skills previously lived in a private repo that fanned them out to each
runtime's skill directory by symlink. This repo replaces that setup: the runtime
installs and updates the plugin itself.

## Install

```
/plugin marketplace add ossianhempel/ossian-stack
/plugin install ossian-stack@ossian-stack
```

On the Mac you author on, register the local clone instead so edits refresh
without a push:

```
/plugin marketplace add ~/Developer/ossian-stack
```

Codex:

```
codex plugin marketplace add ossianhempel/ossian-stack
```

Full detail — including why edits are not live until you refresh — is in
[`docs/plugin-workflow.md`](docs/plugin-workflow.md).

## Layout

| Path | What |
| --- | --- |
| `.claude-plugin/plugin.json` | Claude Code plugin manifest |
| `.claude-plugin/marketplace.json` | Marketplace manifest (this repo hosts itself) |
| `.codex-plugin/plugin.json` | Codex plugin manifest, same `skills/` tree |
| `skills/` | The skills. One directory each, `SKILL.md` entry point |
| `skills/sources.json` | Upstream origin + refresh command for every skill |
| `commands/` | Slash commands (currently empty) |
| `docs/` | Repo docs |
| `bin/docs-list` | Docs indexer — lists `./docs` for whatever repo you run it in |
| `scripts/docs-list.ts` | Implementation behind `bin/docs-list` |
| `AGENTS.md` | Agent instructions for working in this repo (`CLAUDE.md` symlinks to it) |

## Conventions

- Skills go in `skills/<name>/` and must include `SKILL.md`. Kebab-case names.
- Every new skill needs a `skills/sources.json` entry.
- Bump `version` in all three manifests together — they must agree.
- Skills are addressed as `ossian-stack:<name>`.
- Never edit the installed copy under `~/.claude/plugins/cache/`.
