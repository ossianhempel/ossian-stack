# Content Repurposing

Re-cut an existing piece for the requested channels. Preserve its actual claim, evidence, and writer's point of view. Each output must make sense to someone who has never seen the source. Do not reduce the job to summaries, excerpts, or the same text with different line breaks.

## Find the source and voice

1. Start with the supplied text or named artifact. If Ossian refers to “my article,” “my writing,” or an Obsidian note without a path, use `obsidian` to resolve the live vault and search its current writing and notes locations for the specific piece. Follow the vault's current instructions and writing workflow. For a published ossianhempel.com article, follow the vault record to the canonical site source rather than treating its record as the prose.
2. For work under Ossian's own name, read the live vault root `VOICE.md` and `STYLE.md`, and any relevant curated `examples/`. `VOICE.md` governs sound; `STYLE.md` governs the claim, evidence, and reader payoff. These guides are provisional, so honor explicit instructions for this piece and avoid copying example phrasing. Use a project-specific voice guide if the request belongs to another writer or brand. Do not apply Ossian's personal voice to app marketing.
3. Extract the source's central claim, the strongest concrete example or demonstration, its real limits, and the audience's useful takeaway. Keep a short source map for facts, quotations, and first-person experience. A private note or imported highlight is research, not proof that Ossian personally did something. Do not invent runs, results, metrics, testimonials, scenes, or footage.
4. Follow the source language or the user's requested language. If making Swedish and English versions, rewrite each for its reader rather than translating line by line.

If the source is thin or the argument changes meaning when shortened, ask for the missing fact or mark a specific placeholder. Still draft the supported parts. Ask before choosing between genuinely different theses in the writer's name.

## Choose the work requested

- For X or TikTok, read [short-form.md](references/short-form.md). Produce only the requested channel when the user names one; do both when asked for both.
- For a YouTube idea or script, read [youtube.md](references/youtube.md). If asked for an idea and manuscript, supply a selected concept and a complete first script draft, unless choosing the concept would require an unresolved thesis decision.
- When all three are requested, make distinct cuts from the same source. The X post should carry one portable point, the TikTok should show a moment or demonstration, and the YouTube draft should develop the question the source can sustain. They need not repeat the same hook.

Keep this skill focused on transformation. If the user wants to originate or repair the underlying essay, follow the active writing home's drafting workflow first. Ossian's vault maps its writing stages to the available Compound Writing skills; use only the stage needed. For a requested persuasion audit or topic research, use `online-writing`, which diagnoses and does not draft. For an app ad or conversion piece, use `copywriter` and its video guidance. Use `unslop` or the writing home's voice review for a targeted final pass when the draft sounds generic; give a cold reader the cut alone when it may depend on missing context. Do not run every skill by default.

## Finish and hand off

- Deliver copy and script that can be reviewed directly, with visual or performance cues only where they help production. Name the source and voice guides used. Separate facts present in the source from proposed framing or placeholders.
- Check each output for a first-line or first-seconds payoff, standalone value, source fidelity, platform fit, and the writer's actual sentence style. Cut generic advice, repeated claims, engagement bait, and automatic sales calls.
- Do not publish, schedule, upload, or change a vault piece's stage as part of drafting. If the user requests saved drafts, follow the destination's existing conventions, read before writing, and keep derivatives linked to their source.
