# Handoff comment

Copy this file to the project's `docs/agents/handoff-comment.md` and delete this
line. It is the shape of every progress, blocked, and done comment an agent posts
on a ticket. The comment thread is the ticket's working log: a fresh agent
resumes from the last comment without re-deriving the work, and the human
reviews the thread instead of a transcript.

---

# Handoff comment

Post one at every checkpoint: a unit of work verified, a pivot or revert, a
blocker, a pause, and completion. Not after every action. Every comment starts
with the AI disclaimer the project's triage config prescribes.

```
> *This was generated by AI.*

**Status:** in-progress | blocked | paused | done
**Branch / head:** <branch> @ <short SHA>   **PR:** <link or none>

**Done since last comment**
- what landed, one line each, with evidence (commit, test run, screenshot path)

**Verified**
- which acceptance boxes are ticked and what proved them; say "nothing yet" if so

**Deviations**
- anything done differently from the brief, and why

**Next step**
- the first concrete action on resume

**Gotchas**
- traps the next agent must know: flaky test, env quirk, a decision that looks
  wrong but is deliberate
```

A **blocked** comment adds one block and then releases the claim:

```
**Question**
- the precise question, one line
- options, with the recommended one first
- the default if nobody answers, and by when
```

A **paused** comment is a blocked comment without a question: the work is
durable (a `wip:` commit if the tree was dirty, tree state stated in one line)
and the claim is released so another session can pick it up.

A **done** comment states which acceptance boxes are ticked, the PR, and what
was actually run to prove it. It moves the ticket to review; a human, or a
merge-triggered hook, moves it to done.

Plain words, concrete actions, evidence as pointers. If a line does not fit on
one line, the decision is not crisp yet.
